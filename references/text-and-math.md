# 文字层分流与数学核验

PDF 可以包含数字文本对象、整页扫描图，也可以在扫描图上叠加看不见的 OCR 文字。能复制文字不代表这些文字、上下标或位置正确。本工具逐页检查文字量、图片面积、不可见文本模式、异常编码、数学符号与矢量内容；输出仅为分类证据，不是准确率评估。

默认 balanced 会沿用 Marker 的原生文字提取/识别修复路径，不对所有数字 PDF 强制整页 OCR。只有选定页段全部符合扫描特征时，扫描模式才强制 OCR；混合书保留逐页处理机会。先检查 `--inspect`，按原 PDF 页序选代表页；确认纯文字章节结构、脚注、顺序与首尾完整后，才使用 fast。复杂页保留 balanced，数学识别保持开启，不能为了提速设置全局 `disable_ocr`。

文字层公式被扁平化、编号聚集在同一个块、bbox 重叠或超出实际公式区域时，针对原页进行一次 `--force-ocr` 修复。修复后仍须逐式核验：

1. 上标/下标，包括 `H/F`、`fg/gf/hf/fh`，大小写也有意义。
2. 分式分子与分母范围、括号范围、乘法项、负号及比较符号。
3. 公式编号、出现次序、整式是否漏失或重复。
4. 原文中疑似笔误先保留，不能按自己的经济模型理解改成另一公式。

`math_signals.py` 检查输出中的结构异常，并对存在展示公式的页明确要求复核。它不能比较数学语义，不能发现所有错下标；`math_accuracy_status=unreviewed` 不因页序校验或命令成功而变成 verified。公式在正文中出现但无展示块时，仍需核验行内符号。

一次针对性修复后仍无法可靠转写，应保留公式原图或原页图，并在旁文件记录未核验状态，不猜写 LaTeX。使用经过原图核对的 LaTeX 时，将具体修改及核验范围记录在修订说明；不让报告暗示正文或全部行内公式也已校对。
