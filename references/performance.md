# 速度参数与本地服务复用

先用 `--inspect` 或 `pdf_triage.py` 逐页检查。输出的 fast 候选仅表示暂未发现复杂信号；不可见 OCR 层、整页图像、有数学符号或复杂矢量内容的页保持 balanced。默认 balanced 也会利用原生文字，不等于对数字书全页 OCR。混合书只在选定段全部是扫描特征时强制全段 OCR。对照纯文字章节的代表页后才选择 fast 原页段；不全局关闭 OCR，不为格式和速度丢失公式。

选择固定、相同的代表页集（约20页），覆盖正文、数字表格、脚注、图片、页首尾。比较balanced单槽与候选并行槽，必要时比较fast；fast使用不同layout模型，未缓存时先说明下载与测试成本。不能仅凭模式名替换生产质量参数。

统计完整wall time与quality_report.conversion_seconds，模型加载、转换、整理分别解释。页数、复杂度、GPU、并行槽、上下文和模型版本必须可复核。并行增加时保留每槽默认上下文预算，禁止为省显存压小上下文导致截断。

本机RTX3500 Ada 12GB、Marker2.0/Surya0.22的固定20页试验：单槽319.436秒、双槽246.169秒，转换阶段缩短22.94%；完整调用333.83秒与257.66秒。19页规范化文本、脚注标记与表格行数相同；报纸图片页结果有差异，两种均需图像修复。因此双槽可以在通过新书样本核对后采用，不能声称普遍翻倍或零质量风险。

连续分段复用官方SURYA_INFERENCE_KEEP_ALIVE，可省重复模型加载。`batch_convert.py --reuse-server`仅追踪本次新启动的llamacpp服务，结束或失败时核对PID及创建时间后终止；已有服务不属于本任务时不终止。没有必要开启远程端点或多个PDF同时占GPU。原PDF配page-range分段，不建立页码重置的临时PDF。
