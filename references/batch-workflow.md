# 多本扫描书：效率、清单与中断恢复

只有用户请求转换其项目中的文献时才执行本流程；安装 Skill 不授权扫描或转换其他目录。

1. 列出用户指定目录的 PDF，记录相对路径、完整源 PDF 页数、SHA-256 与可用 OCR 环境。用相对路径加短 hash 为每本书建立独立输出目录，避免不同目录同名书混淆。
2. 建立项目 `conversion_manifest.json` 或 CSV：source_id、source_path、source_sha256、total_pages、页段（Marker 从 0 开始）、状态 pending/running/converted/needs_review/failed、输出路径、异常、页码核验状态、实际耗时。只有对应输出和页码覆盖检查通过才能标 converted；converted 不等于人工校对完成。
3. 每本书选代表页检查文字、目录、金额/表格、印刷页码及页首尾；同一排版类型可复用参数，但不能把一本书的印刷页码偏移套给另一书。若含竖排、跨页表格、双页扫描，先确认该类页面能可靠处理。
4. 默认一次只运行一个转换作业，沿用当前解释器和已缓存模型。连续分段一般 20–60 页，根据页数/内存/复杂度调整。命令始终传**原始完整 PDF**和 `--page-range`，不为了分段生成页码重置的临时 PDF。可使用 `scripts/batch_convert.py <明确PDF列表> --output <工作目录> --segment-pages 60 --reuse-server`；并行槽根据固定样本实测决定，默认为1。
5. 每段成功后记录最终 stdout 返回的真实 MD 路径；已有目录可能有 run 子目录，不能假定固定路径。核对预期原 PDF 页码集合与 page_map、quality_report、页面首尾，确认无缺页/重复后记 converted 或 needs_review。失败段保留日志；明确可修复问题最多修复重试一次。
6. 用户请求继续时按来源 hash、原 PDF 页段、实际产物核对清单，跳过已成功段。源 PDF 改变时不要拿旧结果冒充新结果。缺少清单时据已有 provenance 重建事实，不能凭文件存在推断完成。
7. 每本书完成后按**PDF 页码**排序整合，要求 page_map 覆盖所有请求页且无重复。跨段首尾不重写原文，不合并到丢失原始页界。重写汇总 MD 的 assets 相对路径时先验证文件存在；保留分段原件，并在整本索引列出各段链接。避免直接拼接成错误图片路径或多份相同锚点。
8. 批次报告总页数、实际成功页数、失败/待核段、印刷页码核验数量、文字校对范围及实测速度。按各书代表页更新估时，转换与人工校对分别统计；不要承诺 OCR 正确率或把估计当实测。

原先本机 RTX 3500 Ada（12 GB）样本的 Marker 日志：缓存后 4 页约 40.8 秒（不包含 wrapper 的 CLI 检查、整理及人工校对）。这只是普通中文页的历史样本；不是这 30 本书的性能测试。复杂表格、模糊图像、竖排、长页、服务启动、重试与核验都会改变耗时。不为提速默认降分辨率、禁用 OCR/页码、启用未知并发或丢表。

`batch_convert.py` 维护分段清单并在来源hash、输出路径与页码覆盖一致时跳过已成功段。恢复时保持相同分段大小；它不自动核验印刷页码，不自动合并整书，也不以文件存在代替来源检查。合并与页码核验仍按上面的独立流程完成。
